# Healine · Polar 회복·활동 캘린더

Polar Vantage V3의 데이터를 Google Calendar `Healine 상태`에 기록하는 Apps Script입니다. 15분마다 수집하고, 캘린더에 하루 흐름·시간대별 관측·분석용 집계를 남깁니다. 일정과 함께 후속 분석을 할 수 있도록 측정 시각, 단위, 누락 여부와 개인 비교 근거를 보존합니다. 별도 화면이나 체크인 입력은 필요하지 않습니다.

## Healine 운영 경로

플랫폼 연결 후에는 `Polar → Apps Script → Healine DB → Apps Script → Google Calendar`로 동작합니다. 인증과 Google Calendar 쓰기는 기존 Apps Script가 담당하고, 원본 보관·정규화·재처리·수집 상태 조회는 Healine 서버가 담당합니다. [설치와 운영 절차](../../docs/deployment/polar-calendar-integration.mdx)를 따르세요.

서버 연결 전에는 기존 단독 수집이 유지됩니다. 연결 후 Polar 인증이 만료되면 서버에 이미 저장된 관측을 읽고 캘린더에 수집 중단 이유를 표시합니다. 서버 자체에 접근하지 못하면 기존 기록을 유지합니다. 다른 수집 경로로 자동 전환하지 않습니다.

## 캘린더에 표시하는 내용

| 기록 | 표시 내용 |
|---|---|
| 하루 요약 | 해당 날짜의 Polar 회복·ANS 단계, 야간 환산 심박·HRV와 이전 밤 비교, 수면 구간·연속성·견고성 점수, 시간대별 심박 범위·걸음·활동 시간·비교 경계 초과 구간 수, 수신 범위 |
| 시간대별 기록 | 한 시간당 최대 1개 이벤트. 설명에 각 15분의 심박 중앙값·최소·최대·샘플 수·실제 측정 범위, MET 평균·최대, 걸음·수신 범위, 개인 기준·차이·비교 자료 수 |
| 분석용 집계 | 시간대별 설명에 관측 샘플을 시각별로 묶은 1분 집계와 15분 비교 근거. 하루 설명에 회복·수면·시간대별 흐름·수집 상태. 버전과 단위가 있는 JSON으로 후속 분석에 사용 |
| 수면 구간 | Polar에 기록된 수면 시작–종료 시간. 수면 읽기 권한을 추가한 뒤 표시 |
| 내 메모 | 하루 요약과 시간대별 기록의 `[내 메모]` 아래에 선택적으로 적은 내용은 이후 자동 갱신에서도 보존 |

새 기록은 알림을 보내거나 일정을 바쁜 시간으로 막지 않습니다. 아무 관측도 없는 시간대에는 일정을 새로 만들지 않습니다. 이미 있는 시간대의 관측이 최신 응답에서 사라지면 `관측 미수신`으로 갱신하고 메모는 보존합니다. 심박이 없어도 걸음이나 MET가 수신되면 기록하며, 측정된 0보도 보존합니다. 심박의 실제 측정 시각을 표시하므로 캘린더 갱신 시각과 구분할 수 있습니다.

예시입니다. 실제 사용자 측정값이 아닙니다.

```text
🌿 회복 다소 낮음 · 수면 구간 6시간 20분 · 관측 3,240보
🚶 활동 기록 · 94 bpm · 820보
🫀 비슷한 활동 대비 심박 ↑ · 84 bpm
😴 수면 구간 · 6시간 20분
```

`비슷한 활동 대비 심박 ↑`는 현재·직전 활동량과 시각이 비슷한 과거 기록의 표시 경계를 같은 한 시간 안의 두 구간 이상에서 연속으로 넘었을 때 표시됩니다. 30분 내내 높은 심박이었다는 뜻이나 스트레스 진단이 아닙니다. 한 시간 경계에 걸친 두 구간은 현재 묶지 않습니다.

## 캘린더에서 후속 분석하기

이벤트 설명의 `[HEALINE_DATA_V1]`과 `[/HEALINE_DATA_V1]` 사이에 JSON 한 개가 있습니다. `schema`는 `healine.calendar.v1`, `kind`는 `hour` 또는 `day`입니다. 모든 타임스탬프는 UTC ISO 8601이고, 날짜·표시 시간대는 `Asia/Seoul`입니다. `null`은 미수신 또는 비교 불가이며, 실제 0과 다릅니다. `storage`는 해당 관측을 읽은 경로로 플랫폼 연결 시 `healine-platform`입니다.

자동 분석에는 이 블록이 있는 기록을 사용하세요. 이전 15분 이벤트나 하루·시간대·분 집계를 서로 다른 측정으로 합산하지 않습니다. `day`는 개요, `hour`는 상세 데이터이며 서로 겹치는 관측입니다.

실제 캘린더에서 긴 설명이 잘리는 사례를 확인해, 생성할 설명과 메모를 합쳐 8,000자 이내로 제한합니다. 길어지면 설명 문장만 줄이고 JSON 샘플·비교 근거·메모를 유지합니다. 모두 담을 수 없으면 기존 이벤트를 수정하기 전에 중단하고 해당 날짜를 대기 상태로 남깁니다. 읽기 점검은 본문 끝의 표식이 잘려도 이벤트 태그로 찾아 손상된 분석 블록을 보고합니다.

- **시간대별 기록:** `minutes`는 `minuteColumns` 순서의 행 배열입니다. 샘플 시각을 1분으로 묶은 시각, 심박 중앙값·최소·최대(bpm), 심박 샘플 수, 관측 걸음 합, MET 샘플 평균·샘플 수를 담습니다. 최대 60행이며 관측이 없는 분은 생략합니다. `quarters`는 각 15분의 측정 범위·활동 수신 범위·관측 상태·개인 비교 근거를 담습니다.
- **하루 기록:** `recovery`는 해당 날짜의 Polar 회복 단계, ANS 평가(1~5), ANS 값, 평균 박동 간격(ms), RMSSD(ms)와 제공된 개인 기준입니다. `overnightPersonalComparison`은 이전 14일의 수신된 밤을 따로 비교합니다. `sleep`은 각성을 포함하는 시작–종료 구간과 Polar 점수·세부 점수입니다. 세부 점수는 100점 척도이며 효율 비율이나 각성 시간이 아닙니다. `hours`는 `hourColumns` 순서의 시간대별 집계, `collection`은 종류별 수집 상태와 마지막 조회 시각입니다. `analyzedThrough`는 계산한 구간의 끝이며, 마지막 실제 심박 측정은 `heartRate.lastAt`입니다. 조회 시각은 측정 시각과 다릅니다.

1분 행은 그 분 전체를 연속 측정했다는 뜻이 아닙니다. MET는 시간 가중치 없는 관측 샘플 평균이며, 걸음은 해당 분에 시작하는 샘플의 합입니다. 비어 있는 분을 보간하지 않습니다. 시간대별 대표 심박은 15분 중앙값들의 중앙값이고, 최소–최대는 실제 관측 샘플의 범위입니다. 이 범위로 HRV를 계산하지 않습니다. 개인 경계 초과 횟수는 비교가 가능했던 구간 수와 함께 읽어야 합니다.

`modelVersion: 3`은 활동 조건을 맞춘 비교입니다. `comparisonEligible`과 `comparisonReason`은 비교 대상을 고른 이유, `referenceDates`는 실제 사용한 과거 날짜를 나타냅니다. `syncWarning`은 새 수집이 중단되어 저장 기록을 표시하는 경우의 이유입니다.

`heartRateObservationStatus`의 `NO_DATA`는 심박 미수신이며, 해당 구간에 활동 기록은 있을 수 있습니다. `recentActivityObserved: false`는 직전 30분의 수신된 MET 샘플에서 활동을 찾지 못했다는 뜻입니다. 충분히 관측했는지는 `recent30MinMetCoverageMinutes`로 확인하며, 이 자료가 전혀 없으면 `null`입니다. 기존 이벤트가 최신 응답에서 비면 `dataState: no_observations_in_latest_snapshot`과 빈 집계로 갱신합니다. 조회 자체가 실패하면 기존 이벤트를 유지합니다. 플랫폼이 이전 성공 응답을 제공하는 경우에는 그 측정값을 계속 표시하고 하루의 `collection`에서 최신 조회 실패를 확인합니다.

플랫폼 연결 시 전체 원본은 Healine DB에 남습니다. 캘린더는 분 단위 집계와 비교 근거를 제공하므로 원본 샘플을 완전히 재구성하는 용도는 아닙니다. 일정과의 동시 발생·반복 패턴을 분석할 수 있지만, 이 기록만으로 원인이나 본인이 느낀 스트레스를 확정하지 않습니다.

## 비교 기준

이 규칙은 비슷한 상황에서 관측된 심박을 비교하는 **표시 규칙**입니다. 심리적 스트레스 분류기나 확률 모델이 아닙니다. [연구·SDK 검토와 설계 근거](../../docs/deployment/polar-calendar-evidence.mdx)를 참고하세요.

1. 심박 샘플 2개 이상·시간 범위 5분 이상, 현재 15분의 MET·걸음 관측 각각 12분 이상, 직전 30분의 MET 24분 이상을 요구합니다. 걸음 미수신은 0으로 대체하지 않습니다.
2. 현재 평균 MET 2 미만·100보 미만인 구간을 비교 후보로 봅니다. 08:00~22:00만 사용하고, 알려진 수면 구간은 대상과 과거 기준 양쪽에서 제외합니다. 자세·휴식·감정을 확정하는 조건은 아닙니다.
3. 이전 14일에서 시각 차이 90분 이내, 현재 평균 MET 차이 0.35 이내, 걸음 구간(20보 미만/20~99보)이 같고 현재 MET 2 이상 관측 시간 차이 3분 이내인 기록을 찾습니다. 직전 30분의 평균 MET 차이 0.5 이내, MET 2 이상 시간 차이 5분 이내도 요구합니다. 직전에 움직였다는 이유로 모두 버리지 않고, 비슷한 활동 이력을 가진 기록과만 비교합니다.
4. 최소 5개의 과거 날짜와 12개 구간이 필요합니다. 한 날짜의 많은 샘플이 기준을 지배하지 않도록 날짜별 중앙값을 먼저 구합니다. 당일·미래는 제외하고, 마지막 참고 날짜가 4일 넘게 오래되면 비교하지 않습니다.
5. 표시 경계는 `max(날짜별 중앙값들의 90백분위, 중앙값 + 10 bpm, 중앙값 + 3 × 1.4826 × MAD)`입니다. 위 허용 범위와 경계는 공학적 선택이며, 인용 연구에서 검증된 스트레스 기준값이 아닙니다. 비교 자료가 부족하면 이유와 관측값만 표시합니다.

야간 비교는 해당 날짜보다 앞선 14일의 수신 밤 중 최소 5밤을 사용합니다. 야간 HRV와 평균 박동 간격에서 환산한 심박의 중앙값을 따로 계산합니다. Polar 자체의 평소 기준과 혼합하지 않습니다. 수면 회복이나 ANS 점수를 낮 심박에 가산하지 않습니다. 수면 권한이 없거나 기록이 누락되면 알려지지 않은 낮잠을 제외할 수 없습니다.

## 데이터의 의미

- 회복 단계는 **해당 날짜**의 Polar Nightly Recharge입니다. 어제 회복을 오늘 값처럼 표시하지 않습니다.
- 야간 HRV는 Polar의 RMSSD 값(ms)입니다. 야간 심박은 Polar가 제공한 평균 박동 간격(ms)을 `60000 / 간격`으로 환산한 값입니다. 개인 기준도 같은 방식으로 표시합니다.
- 수면 구간 길이는 시작–종료의 차이로 중간 각성을 포함합니다. 실제 잠든 시간과 동일하지 않습니다. 수면 점수는 제공되는 경우 **Polar 수면 점수**라고 출처를 표시합니다.
- 걸음은 조회된 샘플의 합계입니다. 미수신은 0보가 아닙니다. 중복 시각은 한 번만 계산하고, 여러 장치가 있으면 하루에 데이터가 가장 많은 활동 장치 하나를 사용합니다.
- MET 2 이상 시간은 그 값이 기록된 분 수입니다. 몇 개의 샘플을 15분 전체 활동으로 부풀리지 않습니다.
- 개인 비교 규칙의 테스트는 계산·결측 처리·날짜 경계가 맞는지 확인합니다. 감정이나 스트레스 감지 정확도를 검증하는 테스트가 아닙니다.

## 동기화와 기존 기록

현재 날짜와 전날을 매번 다시 읽고, 최근 30일의 과거 하루를 추가로 조회하여 캘린더까지 갱신합니다. 보충 대기열이 있으면 먼저 처리하며, 실패한 날짜는 재시도 시간을 기록하고 다른 날짜를 계속 처리합니다. AccessLink v4의 활동·수면 상세 API는 하루씩 조회하고, 각 요청의 종료 날짜는 배타적으로 처리합니다. 시계에서 Polar Flow로 동기화되어야 새 데이터가 조회됩니다.

오래된 15분 이벤트에는 사용자가 덧붙인 내용을 확실히 구분할 정보가 없으므로 자동 삭제하지 않습니다. 현재 시간대별 기록은 고유 태그로 갱신합니다. 직접 만든 일정은 그대로 두고, 과거의 Healine 태그가 있는 기록도 같은 방식으로 갱신합니다.

## 기존 설치 업데이트

기존 Apps Script 프로젝트·캘린더·배포 URL을 사용합니다. 배포 대상은 로컬 `.clasp.json`과 배포 스크립트에 고정되어 있습니다. 다른 설치에서 이 대상에 배포하지 마세요.

```bash
scripts/validate-project.sh
scripts/deploy-existing.sh --apply "Healine recovery and activity calendar"
```

설치된 15분 트리거는 업로드된 최신 코드를 실행합니다. 매일 새벽에는 개인 비교 자료를 갱신합니다. 플랫폼 연결 후에는 실행마다 과거 하루를 수집·재분석하고 캘린더도 갱신합니다. 성공한 날짜만 보충 대기열에서 제거합니다. 개인 기준은 저장된 관측으로 만들고, 최근 과거 데이터가 보충되면 다시 계산합니다. 상세 비교 자료는 날짜별 속성으로 나눠 저장해 Apps Script 속성당 9KB 제한을 지킵니다. 이미 과거 기록이 충분하면 설치 후 5일을 기다릴 필요는 없습니다. 같은 시간대의 조건을 충족하는 날이 부족하면 자료가 모일 때까지 비교를 보류하며, 관측 기록은 계속합니다.

### 수면 읽기 추가

기존 연결의 연속 심박·활동·Nightly Recharge 권한은 그대로 사용할 수 있습니다. 수면 시간을 추가하려면 기존 Healine 웹 앱을 열고 **Polar 연결**을 다시 진행해 `sleep:read`를 승인하세요. Client ID·Secret을 새로 만들 필요는 없습니다.

수면 권한이 없거나 수면 API가 일시적으로 실패해도 다른 기록은 계속합니다. 하루 요약에서 `추가 연결 필요`, `조회 실패`, `아직 미수신`을 구분합니다.

## 운영 함수와 설정

| 함수 | 역할 |
|---|---|
| `runHealine()` | 오늘·어제 기록 수집 및 캘린더 갱신 |
| `rebuildBaseline()` | 과거 14일의 활동 조건을 포함한 개인 비교 자료 재생성 |
| `queueHealineBackfill(from, to)` | 종료 날짜를 제외한 최대 60일을 보충 대기열에 등록. 인자 생략 시 최근 30일 |
| `continueHealineBackfill()` | 최대 4일을 수집하고 캘린더에 반영. 실행 시작 후 240초가 지나면 다음 날짜 시작을 보류 |
| `replayStoredHealineCalendar()` | Polar 조회 없이 서버 저장 기록으로 최대 4일의 캘린더 재작성 |
| `repairHealinePlatformConnection()` | 기존 수집기 키로 고정 서버 연결을 검증하고 최근 30일 보충 예약 |
| `getHealineStatus()` | 연결·기준 자료·트리거·최근 실행·오류·보충 대기/완료 정보 확인 |
| `verifyPolarAuthorization()` | 실제 토큰 갱신 후 회복 API를 조회하여 무인 갱신을 확인. 토큰 값은 출력하지 않음 |
| `getHealineCalendarAudit()` | 최근 30일과 오늘의 실제 캘린더 기록 수·형식·중복·비교 구간을 다시 읽어 확인 |
| `setup()` | 기존 계정 연결 후 캘린더·트리거 설치 및 최초 실행 |
| `removeHealineTriggers()` | 자동 실행 중단 |

`POLAR_CLIENT_ID`, `POLAR_CLIENT_SECRET`, `POLAR_REDIRECT_URI`와 표시 이름 설정 `HEALINE_CALENDAR_NAME`은 Script Properties를 사용합니다. 쓰기 대상은 `Config.gs`에 고정된 기존 캘린더 ID이며, 이름이 바뀌어도 새 캘린더를 만들지 않습니다. 토큰·승인 범위·개인 비교 자료·플랫폼 주소·사용자별 수집기 키는 User Properties에 보관합니다. 이전의 `HEALINE_FALLBACK_RESTING_HR` 설정은 더 이상 비교에 사용하지 않습니다.

`invalid_grant`로 끊긴 Polar 연결을 복구하면 최근 30일을 새 조회 대상으로 다시 예약하고 이전 원본 조회 오류의 재시도 대기를 해제합니다. Calendar의 공통 대기 시간은 유지합니다. 저장 기록 재작성만 성공했던 날짜도 Polar 원본을 다시 확인합니다. 상태의 `token_present_not_verified`는 토큰이 저장되어 있다는 뜻이며, 유효한 연결을 검증했다는 뜻은 아닙니다.

Polar의 접근 토큰은 서버가 반환한 `expires_in`을 따라 만료 5분 전에 자동 갱신합니다. 공식 문서는 12시간을 설명하지만 실제 응답의 유효 시간이 다를 수 있으므로 고정된 12시간을 가정하지 않습니다. 로그인 콜백과 갱신 요청은 토큰 전용 잠금을 공유합니다. 이미 교체된 토큰에 대한 늦은 401은 최신 토큰으로 재시도하고, 이전 인증 세대의 실패는 새 연결을 차단하지 않습니다. `tokenLifecycle`에는 갱신 시각·횟수·만료 시각·갱신 토큰 교체 여부와 최근 실패의 HTTP 상태·OAuth 오류 코드만 저장합니다. 토큰 값이나 서버의 원문 오류 설명은 기록하지 않습니다. `invalid_grant`만으로 만료·철회·경합 중 어느 이유인지 단정하지 않습니다.

Google Calendar가 단시간 생성 제한을 반환하면 해당 실행을 멈추고, `backfill.calendarRetryAt`까지 다른 날짜의 캘린더 쓰기도 보류합니다. 대기 중에도 오늘·어제와 보충 대기열의 Polar 원본을 수집합니다. 과거 날짜는 한 번 수집하면 `backfill.sourceDates`에 기록하고, 캘린더 반영이 끝날 때까지 보충 대기열에 유지합니다. 저장 기록 재작성도 이 대기를 지키며, 실패 단계와 최근 오류는 `backfill.lastFailure`에 남습니다. 개별 날짜를 쓰다가 중단되면 완료된 시간대는 유지하고, 다음 실행에서 같은 태그를 찾아 이어갑니다.

```bash
node --test tests/*.test.js
```

## 출처

- [Polar AccessLink v4 공식 사양](https://www.polar.com/polar-api-v4/swagger.yaml): 일별 상세 조회 제한, 날짜 범위, 수면 구조, Nightly Recharge 필드와 단위
- [Polar Nightly Recharge 설명](https://support.polar.com/en/nightly-recharge-recovery-measurement): 회복 단계와 야간 지표의 의미
- [Apps Script CalendarEvent](https://developers.google.com/apps-script/reference/calendar/calendar-event): 이벤트 갱신, 태그, 알림, 일정 시간 차단 설정
- [Google Calendar 이벤트 형식](https://developers.google.com/workspace/calendar/api/v3/reference/events): 후속 분석에서 읽는 이벤트 시각과 설명

인증 갱신이 `invalid_grant`로 거절되면 유효하지 않은 갱신 토큰을 반복 호출하지 않습니다. 기존 웹 앱의 **Polar 연결**에서 재승인하면 차단 상태가 해제됩니다. 저장 기록 재작성의 완료는 새 Polar 조회의 완료와 다릅니다. 원본이 없는 날짜를 임의로 채우지 않습니다. `lastResult`, `lastError`, `lastBackfill`을 함께 확인하세요.

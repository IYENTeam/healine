# Healine · Polar 회복·활동 캘린더

Polar Vantage V3의 데이터를 Google Calendar `Healine 상태`에 기록하는 Apps Script입니다. 15분마다 수집하고, 캘린더에 하루 흐름·시간대별 관측·분석용 집계를 남깁니다. 일정과 함께 후속 분석을 할 수 있도록 측정 시각, 단위, 누락 여부와 개인 비교 근거를 보존합니다. 별도 화면이나 체크인 입력은 필요하지 않습니다.

## Healine 운영 경로

플랫폼 연결 후에는 `Polar → Apps Script → Healine DB → Apps Script → Google Calendar`로 동작합니다. 인증과 Google Calendar 쓰기는 기존 Apps Script가 담당하고, 원본 보관·정규화·재처리·수집 상태 조회는 Healine 서버가 담당합니다. [설치와 운영 절차](../../docs/deployment/polar-calendar-integration.mdx)를 따르세요.

서버 연결 전에는 기존 단독 수집이 유지됩니다. 연결 후 서버에 접근하지 못하면 해당 실행을 실패로 남기며, 기존 캘린더 기록을 유지합니다. 다른 수집 경로로 자동 전환하지 않습니다.

## 캘린더에 표시하는 내용

| 기록 | 표시 내용 |
|---|---|
| 하루 요약 | 해당 날짜의 Polar 회복 단계, 야간 심박·HRV와 개인 기준 비교, 수면 구간·점수, 시간대별 심박 범위·걸음·활동 시간·비교 경계 초과 구간 수, 수신 범위 |
| 시간대별 기록 | 한 시간당 최대 1개 이벤트. 설명에 각 15분의 심박 중앙값·최소·최대·샘플 수·실제 측정 범위, MET 평균·최대, 걸음·수신 범위, 개인 기준·차이·비교 자료 수 |
| 분석용 집계 | 시간대별 설명에 관측 샘플을 시각별로 묶은 1분 집계와 15분 비교 근거. 하루 설명에 회복·수면·시간대별 흐름·수집 상태. 버전과 단위가 있는 JSON으로 후속 분석에 사용 |
| 수면 구간 | Polar에 기록된 수면 시작–종료 시간. 수면 읽기 권한을 추가한 뒤 표시 |
| 내 메모 | 하루 요약과 시간대별 기록의 `[내 메모]` 아래에 선택적으로 적은 내용은 이후 자동 갱신에서도 보존 |

새 기록은 알림을 보내거나 일정을 바쁜 시간으로 막지 않습니다. 아무 관측도 없는 시간대에는 일정을 새로 만들지 않습니다. 이미 있는 시간대의 관측이 최신 응답에서 사라지면 `관측 미수신`으로 갱신하고 메모는 보존합니다. 심박이 없어도 걸음이나 MET가 수신되면 기록하며, 측정된 0보도 보존합니다. 심박의 실제 측정 시각을 표시하므로 캘린더 갱신 시각과 구분할 수 있습니다.

예시입니다. 실제 사용자 측정값이 아닙니다.

```text
🌿 회복 다소 낮음 · 수면 구간 6시간 20분 · 관측 3,240보
🚶 활동 기록 · 94 bpm · 820보
🫀 낮은 활동에 심박 ↑ · 84 bpm
😴 수면 구간 · 6시간 20분
```

`낮은 활동에 심박 ↑`는 움직임이 적게 기록된 15분 구간이 같은 한 시간 안에서 두 번 이상 연속으로 개인 비교 경계를 넘었을 때 표시됩니다. 30분 내내 높은 심박이었다는 뜻이나 스트레스 진단이 아닙니다. 한 시간 경계에 걸친 두 구간은 현재 묶지 않습니다.

## 캘린더에서 후속 분석하기

이벤트 설명의 `[HEALINE_DATA_V1]`과 `[/HEALINE_DATA_V1]` 사이에 JSON 한 개가 있습니다. `schema`는 `healine.calendar.v1`, `kind`는 `hour` 또는 `day`입니다. 모든 타임스탬프는 UTC ISO 8601이고, 날짜·표시 시간대는 `Asia/Seoul`입니다. `null`은 미수신 또는 비교 불가이며, 실제 0과 다릅니다. `storage`는 해당 관측을 읽은 경로로 플랫폼 연결 시 `healine-platform`입니다.

자동 분석에는 이 블록이 있는 기록을 사용하세요. 이전 15분 이벤트나 하루·시간대·분 집계를 서로 다른 측정으로 합산하지 않습니다. `day`는 개요, `hour`는 상세 데이터이며 서로 겹치는 관측입니다.

- **시간대별 기록:** `minutes`는 `minuteColumns` 순서의 행 배열입니다. 샘플 시각을 1분으로 묶은 시각, 심박 중앙값·최소·최대(bpm), 심박 샘플 수, 관측 걸음 합, MET 샘플 평균·샘플 수를 담습니다. 최대 60행이며 관측이 없는 분은 생략합니다. `quarters`는 각 15분의 측정 범위·활동 수신 범위·관측 상태·개인 비교 근거를 담습니다.
- **하루 기록:** `recovery`는 해당 날짜의 Polar 회복 단계, 평균 박동 간격(ms), RMSSD(ms)와 각 개인 기준입니다. `sleep`은 각성을 포함하는 시작–종료 구간과 Polar 점수입니다. `hours`는 `hourColumns` 순서의 시간대별 집계, `collection`은 종류별 수집 상태와 마지막 조회 시각입니다. `analyzedThrough`는 계산한 구간의 끝이며, 마지막 실제 심박 측정은 `heartRate.lastAt`입니다. 조회 시각은 측정 시각과 다릅니다.

1분 행은 그 분 전체를 연속 측정했다는 뜻이 아닙니다. MET는 시간 가중치 없는 관측 샘플 평균이며, 걸음은 해당 분에 시작하는 샘플의 합입니다. 비어 있는 분을 보간하지 않습니다. 시간대별 대표 심박은 15분 중앙값들의 중앙값이고, 최소–최대는 실제 관측 샘플의 범위입니다. 이 범위로 HRV를 계산하지 않습니다. 개인 경계 초과 횟수는 비교가 가능했던 구간 수와 함께 읽어야 합니다.

`heartRateObservationStatus`의 `NO_DATA`는 심박 미수신이며, 해당 구간에 활동 기록은 있을 수 있습니다. `recentActivityObserved: false`는 직전 30분의 수신된 MET 샘플에서 활동을 찾지 못했다는 뜻입니다. 충분히 관측했는지는 `recent30MinMetCoverageMinutes`로 확인하며, 이 자료가 전혀 없으면 `null`입니다. 기존 이벤트가 최신 응답에서 비면 `dataState: no_observations_in_latest_snapshot`과 빈 집계로 갱신합니다. 조회 자체가 실패하면 기존 이벤트를 유지합니다. 플랫폼이 이전 성공 응답을 제공하는 경우에는 그 측정값을 계속 표시하고 하루의 `collection`에서 최신 조회 실패를 확인합니다.

플랫폼 연결 시 전체 원본은 Healine DB에 남습니다. 캘린더는 분 단위 집계와 비교 근거를 제공하므로 원본 샘플을 완전히 재구성하는 용도는 아닙니다. 일정과의 동시 발생·반복 패턴을 분석할 수 있지만, 이 기록만으로 원인이나 본인이 느낀 스트레스를 확정하지 않습니다.

## 비교 기준

1. 최근 14일 중 비교할 날짜보다 **이전** 데이터만 사용합니다.
2. 심박 샘플이 2개 이상이고 최소 5분 간격으로 퍼져 있어야 합니다. 활동 데이터는 15분 중 12분 이상 필요합니다.
3. 평균 MET 1.5 미만, 모든 관측 MET 2 미만, 관측된 걸음이 20보 미만인 구간을 낮은 활동으로 구분합니다. 직전 30분에도 활동 데이터가 24분 이상 있고 MET 2 이상이 없어야 비교합니다. 이 조건은 자세나 감정을 판정하지 않습니다.
4. 같은 시간대의 하루별 심박 중앙값을 모읍니다. 최소 5일·12구간이 없으면 `개인 비교 기준 누적 중`으로 표시합니다. 임의의 휴식심박으로 대체하지 않습니다.
5. 표시 경계는 `max(개인 90백분위, 중앙값 + 10 bpm, 중앙값 + 3 × 1.4826 × MAD)`입니다. 이 값은 작은 변동을 과장하지 않기 위한 **표시 규칙**이며 의학적으로 검증된 스트레스 경계가 아닙니다. 마지막 비교 자료가 4일 넘게 오래되면 사용하지 않습니다.

움직임 수치가 위의 낮은 활동 조건을 벗어나거나, 알려진 수면 구간과 겹치거나, 데이터가 부족한 때에는 이 비교를 보류합니다. 야간 22:00–08:00에는 비교하지 않고 관측값만 기록합니다. 수면 권한이 없으면 낮잠 등 실제 수면 여부를 구분할 수 없고, 낮 시간의 개인 기준에도 수면이 섞일 수 있습니다. Nightly Recharge는 낮 심박에 가산하지 않고 별도의 회복 정보로 보여줍니다.

## 데이터의 의미

- 회복 단계는 **해당 날짜**의 Polar Nightly Recharge입니다. 어제 회복을 오늘 값처럼 표시하지 않습니다.
- 야간 HRV는 Polar의 RMSSD 값(ms)입니다. 야간 심박은 Polar가 제공한 평균 박동 간격(ms)을 `60000 / 간격`으로 환산한 값입니다. 개인 기준도 같은 방식으로 표시합니다.
- 수면 구간 길이는 시작–종료의 차이로 중간 각성을 포함합니다. 실제 잠든 시간과 동일하지 않습니다. 수면 점수는 제공되는 경우 **Polar 수면 점수**라고 출처를 표시합니다.
- 걸음은 조회된 샘플의 합계입니다. 미수신은 0보가 아닙니다. 중복 시각은 한 번만 계산하고, 여러 장치가 있으면 하루에 데이터가 가장 많은 활동 장치 하나를 사용합니다.
- MET 2 이상 시간은 그 값이 기록된 분 수입니다. 몇 개의 샘플을 15분 전체 활동으로 부풀리지 않습니다.
- 개인 비교 규칙의 테스트는 계산·결측 처리·날짜 경계가 맞는지 확인합니다. 감정이나 스트레스 감지 정확도를 검증하는 테스트가 아닙니다.

## 동기화와 기존 기록

현재 날짜와 전날을 매번 다시 읽어 늦게 도착한 데이터를 반영합니다. AccessLink v4의 활동·수면 상세 API는 하루씩 조회하고, 각 요청의 종료 날짜는 배타적으로 처리합니다. 시계에서 Polar Flow로 동기화되어야 새 데이터가 조회됩니다.

오래된 15분 이벤트에는 사용자가 덧붙인 내용을 확실히 구분할 정보가 없으므로 자동 삭제하지 않습니다. 현재 시간대별 기록은 고유 태그로 갱신합니다. 직접 만든 일정과 이틀 이전 기록은 그대로 둡니다.

## 기존 설치 업데이트

기존 Apps Script 프로젝트·캘린더·배포 URL을 사용합니다. 배포 대상은 로컬 `.clasp.json`과 배포 스크립트에 고정되어 있습니다. 다른 설치에서 이 대상에 배포하지 마세요.

```bash
scripts/validate-project.sh
scripts/deploy-existing.sh --apply "Healine recovery and activity calendar"
```

설치된 15분 트리거는 업로드된 최신 코드를 실행합니다. 매일 새벽에는 개인 비교 자료를 갱신합니다. 플랫폼 연결 후에는 실행마다 과거 하루를 추가 수집해 최근 14일을 보강하고, 개인 비교 자료는 플랫폼에 저장된 관측에서 만듭니다. 과거 수집 실패는 관리 화면에서 확인해야 합니다. 캘린더의 이틀 이전 기록은 다시 쓰지 않습니다. 이미 과거 기록이 충분하면 설치 후 5일을 기다릴 필요는 없습니다. 같은 시간대의 조건을 충족하는 날이 부족하면 자료가 모일 때까지 비교를 보류하며, 관측 기록은 계속합니다.

### 수면 읽기 추가

기존 연결의 연속 심박·활동·Nightly Recharge 권한은 그대로 사용할 수 있습니다. 수면 시간을 추가하려면 기존 Healine 웹 앱을 열고 **Polar 연결**을 다시 진행해 `sleep:read`를 승인하세요. Client ID·Secret을 새로 만들 필요는 없습니다.

수면 권한이 없거나 수면 API가 일시적으로 실패해도 다른 기록은 계속합니다. 하루 요약에서 `추가 연결 필요`, `조회 실패`, `아직 미수신`을 구분합니다.

## 운영 함수와 설정

| 함수 | 역할 |
|---|---|
| `runHealine()` | 오늘·어제 기록 수집 및 캘린더 갱신 |
| `rebuildBaseline()` | 과거 14일의 낮은 활동 심박 비교 자료 재생성 |
| `getHealineStatus()` | 연결·기준 자료·트리거·최근 실행 정보 확인 |
| `setup()` | 기존 계정 연결 후 캘린더·트리거 설치 및 최초 실행 |
| `removeHealineTriggers()` | 자동 실행 중단 |

`POLAR_CLIENT_ID`, `POLAR_CLIENT_SECRET`, `POLAR_REDIRECT_URI`와 표시 이름 설정 `HEALINE_CALENDAR_NAME`은 Script Properties를 사용합니다. 쓰기 대상은 `Config.gs`에 고정된 기존 캘린더 ID이며, 이름이 바뀌어도 새 캘린더를 만들지 않습니다. 토큰·승인 범위·개인 비교 자료·플랫폼 주소·사용자별 수집기 키는 User Properties에 보관합니다. 이전의 `HEALINE_FALLBACK_RESTING_HR` 설정은 더 이상 비교에 사용하지 않습니다.

```bash
node --test tests/*.test.js
```

- [Polar Nightly Recharge 설명](https://support.polar.com/en/nightly-recharge-recovery-measurement): 회복 단계와 야간 지표의 의미
- [Apps Script CalendarEvent](https://developers.google.com/apps-script/reference/calendar/calendar-event): 이벤트 갱신, 태그, 알림, 일정 시간 차단 설정
- [Google Calendar 이벤트 형식](https://developers.google.com/workspace/calendar/api/v3/reference/events): 후속 분석에서 읽는 이벤트 시각과 설명

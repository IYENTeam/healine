title: "Running with Docker"
description: "Build and run Healine from your checkout with Docker Compose."
---

## Configure

From the repository root:

```bash
cp backend/config/.env.example backend/config/.env
cp frontend/.env.example frontend/.env
```

Set `SECRET_KEY`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` in the backend environment file. The database defaults in Compose and the backend configuration use `healine`. Use a fresh volume when starting this fork; changing these values does not rename an existing database or role.

## Start

```bash
docker compose up -d --build
docker compose logs -f app
```

The portal is at `http://localhost:3000`, API documentation at `http://localhost:8000/docs`, and the task monitor at `http://localhost:5555`. The administrator is seeded only while the developer table is empty.

The development Compose file builds local images, runs the frontend development server, and stores PostgreSQL and Redis data in named volumes.

## Stop

```bash
docker compose stop
```

This preserves the data volumes.

## Production images

Healine's production Dockerfiles can be built locally:

```bash
docker build -t healine-backend:local ./backend
docker build -t healine-frontend:local -f frontend/Dockerfile ./frontend
```

Deploy these with environment-specific credentials, persistent storage, HTTPS, and the service commands from `docker-compose.yml`. The frontend production image uses `VITE_API_URL` at runtime.

Image publishing is opt-in. In GitHub repository settings, configure the `HEALINE_PUBLISH_IMAGES` variable as `true`, set `DOCKERHUB_NAMESPACE`, and supply the `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` secrets. The workflow publishes `healine-backend` and `healine-frontend` in that namespace. Until images have been published, build from source.
